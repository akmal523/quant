## Part 0: Defects Observed in the Current Run

1. Discovery graduates and demotes in the same run. 18 symbols graduated (52-week high), then 15 demoted seconds later ("no signals for 6 months"). Newly graduated assets have no signal history, so the demotion check treats them as stale immediately. The state machine is fighting itself.
2. CORE ETFs were demoted to WATCHLIST. URTH, IWDA.AS, EUNL.DE, VOO, XEON.DE and the entire core set were demoted. The core sleeve must be immutable; demotion should only apply to graduated satellites.
3. Contradictory registry state. The 15:40 export shows `universe_status = WATCHLIST` with `graduated_at` populated for 18 symbols. Status and history disagree.
4. Delisted symbol retried forever. ZNWD.L returns "possibly delisted" every weekly run but is never archived.
5. Broker registry is mostly empty. Routing instructions print `ISIN n/a` for most symbols. A Trade Republic execution instruction without an ISIN is not executable; the TR app searches by ISIN.
6. Inverse ETFs routed to Sparplan. SDS (2x inverse S&P 500) and SH (inverse S&P 500) received SPARPLAN routes. Inverse/leveraged products decay over time and must never be accumulation vehicles.
7. ETF scoring is degenerate. Every ETF gets Structural 85.0, Stewardship 18.0, and all BUYs tie at Active_Score 93.6. Tactical grade is binary (99.4 vs 59.4) because regime bull prob saturated at 0.99. The scanner cannot rank ETFs against each other.
8. Dashboard is half-empty. Volatility bands are not rendered (price line only), the Z-score section is a placeholder, headers contain emojis, and `use_container_width` raises a deprecation warning.
9. Stale data not surfaced. IEAG.L last price is 2026-08-28 (4 days old) and nothing flags it.
10. Fee hurdle is static. Every row shows `min_trade_size_eur = 100` regardless of expected alpha.

## Part 1: Universe State Machine Fixes

### 1.1 `taxonomy.py` - add statuses and structure flags

Statuses become: `CORE`, `ACTIVE`, `WATCHLIST`, `DELISTED`. Add a `structure` column: `PLAIN`, `INVERSE`, `LEVERAGED`.

```python
CORE_STATUSES = {"CORE"}            # never graduated, never demoted
DEMOTABLE_STATUSES = {"ACTIVE"}     # only graduated satellites age out
```

Add functions: `mark_delisted(symbol)`, `add_to_watchlist(symbol, instrument_class)`, `set_core(symbol)`.

### 1.2 `discovery.py` - grace period and CORE immunity

Demotion anchor must be the most recent activity, and new graduates get a grace period:

```python
anchor = max(d for d in [graduated_at, last_signal_at] if d)
if months_between(anchor, now) < config.GRADUATION_GRACE_MONTHS:
    continue  # grace period, do not demote
```

Rules:
- Symbols with status `CORE` are skipped entirely.
- Demotion never runs on a symbol graduated in the current run.
- Track consecutive fetch failures in the registry (`fetch_failures` column). After 3 consecutive failures, set status `DELISTED`, stop fetching, and log an event. ZNWD.L becomes the first case.

### 1.3 `universe_events` table for an audit trail

```sql
CREATE TABLE IF NOT EXISTS universe_events (
    ts TIMESTAMP DEFAULT now(),
    symbol VARCHAR,
    event VARCHAR,      -- GRADUATE / DEMOTE / DELIST / PIN / ADD
    reason VARCHAR
);
```

`discovery.py` writes every state change here. The dashboard reads it (Part 4).

### 1.4 One-off registry repair script

Add `scripts/repair_registry.py`:

## Part 2: Broker Registry and Routing Fixes

### 2.1 Complete the ISIN registry

The registry must contain a valid ISIN for every CORE and ACTIVE symbol. Process:
1. Open the Trade Republic app, search each instrument by name, copy the ISIN (the app is the authoritative source for what is actually tradable on your account).
2. Add a checksum validator so typos fail tests instead of failing at order entry:

```python
def validate_isin(isin: str) -> bool:
    if len(isin) != 12 or not isin.isalnum():
        return False
    body, check = isin[:-1], int(isin[-1])
    digits = "".join(str(int(c, 36)) for c in body)
    total = 0
    for i, ch in enumerate(reversed(digits)):
        d = int(ch)
        if i % 2 == 0:
            d *= 2
            if d > 9:
                d -= 9
        total += d
    return (total + check) % 10 == 0
```

3. `routing.py` refuses to emit a clean instruction when ISIN is missing; instead it emits `instruction = "ISIN MISSING - resolve in broker app before execution"` and the symbol appears in the dashboard Data Health section.

### 2.2 Routing rules for structure

```python
if structure in ("INVERSE", "LEVERAGED"):
    route = "HOLD"   # never SPARPLAN, never CORE bucket
```

### 2.3 Dynamic fee hurdle

`minimum_trade_size()` must use the symbol's expected alpha (active score above threshold), not a constant 100 EUR:

```python
alpha_bps = max(active_score - 50.0, 1.0) * 100   # document this mapping
min_size = ROUND_TRIP_FEE_EUR / (alpha_bps / 10000)
```

The routing export should show varying, meaningful sizes.

## Part 3: Scoring Differentiation (kill the 93.6 tie)

### 3.1 Replace the hardcoded ETF structural grade

`etf_quality_score()` computed cross-sectionally over the ETF subset:

| Component | Weight | Source |
|---|---|---|
| Trend strength z | 0.30 | close vs 200 SMA |
| Relative strength z vs IWDA.AS (6m) | 0.30 | benchmark-relative return |
| Low-vol z (inverse 60d vol) | 0.20 | vol_60d |
| 12m momentum z | 0.20 | ret_12m |

Map the weighted sum to 0-100. This makes EIMI.L, CSPX.L, EUNL.DE rank differently.

### 3.2 Continuous tactical grade for ETFs

Current output is binary (99.4 / 59.4). Blend:

```python
tactical = 50 + 25 * regime_tilt + 25 * tanh(momentum_z)
```

where `regime_tilt = bull_prob - 0.5` scaled, so a saturated 0.99 regime no longer forces every uptrending ETF to the same value.

### 3.3 Populate factor scores for ETFs

Run `factor_scores()` on the ETF subset with the ETF-appropriate columns above and write the rows into `factor_scores.parquet` in the run artifact. The dashboard Z-score section then has real data for every instrument class.

### 3.4 Funnel transparency

### 4.1 Page 1: Daily Briefing

Top metric row (st.metric): Portfolio value EUR, Daily PnL EUR, Cash at 2.25% EUR, Regime bull prob, Last run time.

Section "Actions required today": two tables, one per route.
- SPARPLAN table: Symbol, ISIN (in `st.code` for copying), Amount EUR, one-line instruction.
- ACTIVE TRADE table: Symbol, ISIN, Side, Size EUR, Fee note (1 EUR), fee hurdle pass/fail.
- If both empty: "No actions required."

Section "Bucket check": current Safety / Core / Alpha percentages vs the 10/40/50 constraints, red text on violation. Cash input is a single `st.number_input` persisted to a small `account_state` table.

Section "Data health": stale prices (last date older than `STALE_DATA_DAYS`, e.g. IEAG.L), missing ISINs, delisted symbols, notifier configured yes/no.

Expander "Backtest": latest cost-aware backtest equity curve, net vs gross, cost drag.

### 4.2 Page 2: Asset Explorer

- Selectbox (portfolio holdings first) plus free-text search by symbol or ISIN.
- Identity card: class, status, structure, sector, ISIN, TR ticker, exchange, currency.
- Price chart with the bands actually drawn: close line, 200 SMA line, and a shaded band at close +/- 2 x daily EWMA vol x close (plotly `fill="tonexty"`). Volume as a subplot. This fixes the empty-bands screenshot.
- "Factor profile": horizontal bar chart of the z-scores read from the latest `factor_scores.parquet` (now populated for ETFs too). For equities: value/quality/momentum/low-risk/sentiment; for ETFs: trend/RS/low-vol/momentum.
- Broker card: ISIN copy block, min trade size for this symbol, route recommendation.

### 4.3 Page 3: Universe Manager

- Metric row: counts of CORE / ACTIVE / WATCHLIST / DELISTED.
- Event log table: last 50 rows of `universe_events` (ts, symbol, event, reason). This makes graduation/demotion auditable.
- Filterable registry table: multiselect on status and class, text search, no index column, shows `graduated_at` and `fetch_failures`.
- Actions with confirmation: Pin to ACTIVE, Demote to WATCHLIST, Mark DELISTED, Add to watchlist (symbol + class inputs). All write through `taxonomy.py` functions inside a transaction.

No fourth page. Backtest lives in an expander; settings live in `config.py`. Three focused pages beat five cluttered ones.
