## Adaptations to the real codebase (binding)

The v10.6.3 spec is written against a different stack. Adapt, do not copy:

- The CLI is **argparse** with [`quant/cli/output.py`](quant/cli/output.py)
  `reporter`, not typer/rich. New commands are `_cmd_*` functions plus a
  subparser entry.
- The signal cache is **JSON** (`outputs/signal_cache.json`), not parquet.
- `trade_log` is a **DuckDB table**, not `trade_log.csv`.
- Stewardship is `stewardship_score_v2`, not `calculate_stewardship`.
- `get_instrument_class` lives in [`quant/execution/taxonomy.py`](quant/execution/taxonomy.py).
- The existing `emergency_sell_recommendation(amount, holdings)` stays for
  backward compatibility; the new tier-aware plan is a **new** function.

## Phase 1 — Data integrity and migration edge cases

- `detect_unclassified_assets(portfolio_df, tiers_df)` and
  `auto_assign_tiers(recommendations, tiers_df)` in
  [`quant/portfolio/tier_manager.py`](quant/portfolio/tier_manager.py). Heuristic:
  ETF/CASH to FORTRESS, EQUITY to ALPHA, else SPECULATIVE.
- `validate_tiers_csv(tiers_df, portfolio_df)` and
  `repair_tiers_csv(tiers_df, portfolio_df)` (dedupe, drop orphans, default
  invalid tiers to ALPHA).
- CLI `validate-tiers` and `repair-tiers` (argparse).
- UI: unclassified-asset alert with an auto-assign action.

## Phase 2 — Emergency liquidity edge cases

- New `emergency_sell_plan(amount_needed, portfolio_df, tiers_df)` returning
  `{recommendations, total_available, fortress_warning, shortfall}`. Priority:
  ALPHA, then SPECULATIVE, then FORTRESS (last resort, with a tax warning).
- `prioritize_sells_with_tax(recommendations, tax_rate, freistellungsauftrag)`:
  losers first, then winners within the 1000 EUR allowance, then the rest.
- Update the UI and weekly report to use the new plan.

## Phase 3 — Weekly report edge cases

- Empty-portfolio report with first-step guidance.
- Document automated Friday generation (cron) in the README; no new scheduler
  code beyond a documented helper.

## Phase 4 — Signal cache edge cases

- `load_signal_cache(max_age_days=7)` returns None when stale;
  `invalidate_signal_cache()`.

## Phase 5 — Behavioral guardrails

- `check_alpha_weekly_limit` returns a dict
  `{allowed, trades_remaining, warning, override_required}`.
- `track_weekly_trades(as_of)` counts this week's trades from the DuckDB
  `trade_log`.
- UI: trade-limit warning.
